Issues

Critical 버그 / 기능 손실

C-1: pre-tool-bash.sh / post-tool-bash.sh — stdin 완전 유실로 hook 동작 불가
hooks/pre-tool-bash.sh · hooks/post-tool-bash.sh · hook_voice/hook_handlers.py:167-193

Claude Code PreToolUse/PostToolUse hook은 stdin으로 JSON ({"tool_input": {"command": "..."}, "tool_response": {...}})을 전달한다. 두 hook 스크립트 모두 nohup 백그라운드로 실행하면서 stdin을 파이프하지 않아 raw=""이 되고, json.loads("") → Exception → 즉시 return. 결과적으로 이 두 hook은 아무 소리도 내지 않는다.

영향: 빌드 착수 / 테스트 실행 / 파괴적 명령 경고가 실제로는 동작하지 않는다.

# 현재 (동작 안 함)
nohup "$VENV_PY" -m hook_voice pre-tool-bash > /dev/null 2>&1 &

# 수정 (notification.sh 패턴 따르기)
PAYLOAD=$(cat)
echo "$PAYLOAD" | nohup "$VENV_PY" -m hook_voice pre-tool-bash > /dev/null 2>&1 &

TypeScript 원본도 동일 버그였으므로 마이그레이션 중 기존 버그를 그대로 이식한 것이다.

C-2: subagent-stop.sh — stdin 유실로 transcript_path 미전달, agent_type 추출 실패 위험
hooks/subagent-stop.sh · hook_voice/hook_handlers.py:126-143

Claude Code SubagentStop hook stdin JSON에는 transcript_path가 포함된다 (실제 notification 로그로 확인: "transcript_path": "/Users/.../xxxx.jsonl"). 현재 스크립트는 stdin을 pipe하지 않아 handle_subagent_stop이 data.get("transcript_path", "")를 얻지 못한다.

결과적으로 _extract_agent_type_from_transcript()가 호출되지 않아 agent_type=""이 되고, 모든 서브에이전트가 default voice (F1)를 사용한다. 역할별 다성 TTS가 실질적으로 비활성화된 상태다.

# 수정
PAYLOAD=$(cat)
echo "$PAYLOAD" | nohup "$VENV_PY" -m hook_voice subagent-stop > /dev/null 2>&1 &

Important 아키텍처 / 테스트 gap

I-1: stop.sh — stdin 미전달로 transcript fallback에만 의존
hooks/stop.sh · hook_voice/hook_handlers.py:100-113

Stop hook stdin JSON에도 transcript_path가 있지만 stop.sh가 pipe하지 않는다. handle_hook은 CLAUDE_CODE_SESSION_ID + CLAUDE_PROJECT_DIR 환경변수로 path를 재구성하는 fallback을 갖고 있어 기능은 동작하지만, 환경변수가 없는 상황에서 text가 비어 TTS가 실행되지 않을 수 있다.

# 수정 (notification.sh와 동일한 패턴)
PAYLOAD=$(cat)
echo "$PAYLOAD" | nohup "$VENV_PY" -m hook_voice hook >> /tmp/voice-notification-debug.log 2>&1 &
I-2: config의 edge_timeout_ms / supertonic_timeout_ms가 player.py에서 사용되지 않음
hook_voice/config.py:36-37 · hook_voice/player.py:105, 140

Config에 edge_timeout_ms=10000, supertonic_timeout_ms=20000 필드가 있지만 player.py는 asyncio.wait_for(..., timeout=10.0), timeout=20.0으로 하드코딩. 사용자가 .voice-persona.json에서 설정해도 무시된다.

설정 필드가 존재하지만 동작하지 않는 데드 설정 — API 계약 위반이다. speak_hook, speak_agent에 config를 주입하거나, caller인 hook_handlers.py에서 timeout 값을 계산해 넘겨야 한다.

I-3: handle_subagent_stop, handle_hook_suggest 테스트 없음
tests/test_hook_handlers.py

두 handler가 테스트되지 않았다. 특히 handle_subagent_stop은 load_voice_map → resolve_voice → extract_one_liner → speak_agent 연쇄 호출로 가장 복잡한 경로다. handle_hook의 transcript fallback 경로(_derive_transcript_path → _extract_last_assistant_text)도 테스트 없다.

I-4: _transcript_cache — 프로세스간 공유 불가 (in-memory)
hook_voice/skill_recommender.py:14, 81-103

모듈 레벨 dict으로 TTL 60초 캐시를 구현했지만, 각 hook 호출이 독립 Python 프로세스이므로 캐시가 항상 cold start다. 코드 복잡도만 늘리고 실제 효과가 없다. 제거하거나 파일 기반 캐시 (mtime 비교)로 교체하는 것이 정직하다.

Minor 스타일 / 최적화

M-1: tempfile.mktemp 사용 — deprecated, 이론적 race condition
hook_voice/player.py:45, 141

tempfile.mktemp()는 파일 이름만 반환하고 생성하지 않아 이름 획득과 생성 사이에 race condition이 있다. Python 3에서 공식 deprecated.

# 수정
import tempfile
with tempfile.NamedTemporaryFile(suffix=".mp3", prefix="vp_edge_", delete=False) as f:
    out = Path(f.name)
M-2: stop hook 처리 결과 로깅 없음 — 디버깅 가시성 저하
hooks/stop.sh · hook_voice/__main__.py

Python 버전에서 "[stop] fired" 같은 처리 시작 로그가 사라졌다. 실제 로그 파일에는 TypeScript 시절 남긴 항목만 남아 있어 Python 버전의 동작 여부를 로그로 확인하기 어렵다. __main__.py나 hook_handlers.py에 구조화 로그 1줄 추가를 권장.

M-3: _speak_http에서 config.tts_instruct 미전달
hook_voice/player.py:64

_speak_http 호출 시 "instruct": ""로 하드코딩. config의 tts_instruct가 HTTP TTS 서버 경로에서는 무시된다. EdgeTTS/Supertonic 경로는 instruct 미지원이지만 /speak 경로는 해당 필드를 지원한다.

M-4: llm_client.py — 예외 silencing이 너무 광범위
hook_voice/llm_client.py:36-38

except Exception: return ""가 HTTP 상태 에러, JSON 파싱 에러, 키 누락 에러를 모두 동일하게 처리한다. 적어도 httpx.HTTPStatusError와 KeyError를 개별 except로 분리하면 디버깅이 쉬워진다. 현재는 API 키 오류와 네트워크 오류를 구분할 수 없다.
