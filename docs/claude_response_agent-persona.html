클로드 팀 에이전트에 페르소나 적용하기

Claude Code 멀티 에이전트 팀에서 각 에이전트에 역할·성격·제약을 부여하는 방법

페르소나란?

팀 에이전트에서 페르소나(Persona)는 에이전트의 역할, 말투, 행동 규칙, 전문 영역을 정의하는 시스템 프롬프트입니다. 같은 Claude 모델이라도 페르소나에 따라 "보안 리뷰어", "테스트 작성자", "아키텍트"처럼 전혀 다른 행동을 합니다.

적용 방법은 크게 세 가지입니다.

① Agent 툴 prompt 파라미터 ② .claude/agents/ 커스텀 에이전트 파일 ③ voice-persona 음성 페르소나

1Agent 툴 prompt 파라미터에 직접 주입

가장 빠른 방법. 에이전트를 spawn할 때 prompt 첫 부분에 페르소나 블록을 넣습니다.

권장 패턴

구조: 페르소나 헤더 → 작업 지침

## 당신의 역할
당신은 **보안 리뷰어(Security Reviewer)** 입니다.
OWASP Top 10, 인증/인가 결함, 비밀 노출을 최우선으로 검토합니다.

## 행동 규칙
- 취약점 발견 시 심각도(Critical/High/Medium/Low)를 반드시 표기한다
- 코드를 직접 수정하지 않는다 — 문제점과 권고사항만 리포트한다
- 의심스러운 부분은 False Positive라도 보고한다

## 작업
다음 파일들의 보안 취약점을 분석하세요: ...

실제 코드 예시 — 팀 리더가 에이전트 spawn할 때

Agent({
  description: "보안 리뷰",
  subagent_type: "claude",
  name: "agent-security",
  model: "sonnet",
  prompt: `## 당신의 역할
당신은 보안 리뷰어입니다. OWASP Top 10 기준으로 코드를 검토합니다.

## 행동 규칙
- 취약점 발견 시 심각도(Critical/High/Medium/Low) 표기 필수
- 코드 직접 수정 금지 — 문제점과 권고사항만 리포트
- 완료 후 팀 리더에게 SendMessage로 보고

## 작업
src/auth/ 디렉토리의 보안 취약점을 분석하세요.`
})
팁: 페르소나 블록은 prompt 맨 앞에 위치시켜야 효과가 높습니다. Claude는 시스템 프롬프트가 없을 때 prompt의 첫 지시를 역할 정의로 인식합니다.

2.claude/agents/ 커스텀 에이전트 파일

재사용 가능한 에이전트 페르소나는 .claude/agents/<name>.md 파일로 정의합니다. subagent_type에 파일명(확장자 제외)을 지정하면 해당 시스템 프롬프트가 자동 적용됩니다.

파일 구조

.claude/ └── agents/ ├── security-reviewer.md ← subagent_type: "security-reviewer" ├── test-writer.md ← subagent_type: "test-writer" └── architect.md ← subagent_type: "architect"

에이전트 파일 형식 (security-reviewer.md)

---
name: security-reviewer
description: OWASP 기준 코드 보안 리뷰 전문가. 취약점 탐지, 인증/인가 검증, 비밀 노출 점검.
tools:
  - Read
  - Grep
  - Glob
  - Bash
---

당신은 시니어 보안 엔지니어입니다.
OWASP Top 10, CWE, 공급망 보안을 기준으로 코드를 분석합니다.

## 행동 규칙
- 코드를 직접 수정하지 않는다
- 발견된 모든 취약점에 심각도 레이블(Critical/High/Medium/Low)을 붙인다
- 근거 없는 추측은 하지 않는다 — 코드를 직접 읽은 후 판단한다
장점

커스텀 에이전트 파일의 이점

항목prompt 파라미터agents/ 파일
재사용매번 복붙 필요파일 하나로 팀 전체 공유
툴 제한불가 (전체 툴 상속)frontmatter로 허용 툴 지정
버전 관리prompt 문자열로 추적git으로 이력 관리
페르소나 변경코드 수정 필요md 파일만 편집

spawn 코드

// .claude/agents/security-reviewer.md가 있으면
// subagent_type만 지정해도 페르소나 자동 적용
Agent({
  description: "보안 리뷰",
  subagent_type: "security-reviewer",   // ← 파일명과 일치
  name: "agent-security",
  model: "sonnet",
  prompt: "src/auth/ 디렉토리 보안 리뷰 후 팀 리더에게 SendMessage로 보고."
})

3voice-persona 프로젝트의 음성 페르소나 연동

이 프로젝트에서는 에이전트 타입을 음성 페르소나로도 표현합니다. 서브에이전트가 완료되면 그 역할에 맞는 목소리와 호칭으로 발화합니다.

SubagentStop hook 발화 흐름 transcript.jsonl → subagent_type 추출 (예: "security-reviewer") → voice-map.json에서 voice ID 조회 → getAgentLabel()로 한국어 호칭 변환 → "보안리뷰어입니다. 인증 로직에서 JWT 검증 누락 발견했습니다." → Supertonic / Edge TTS로 재생

voice-map.json 설정 예시

{
  "categories": {
    "reviewer": {
      "label": "리뷰어",
      "voice": "Eric",
      "agents": ["code-reviewer", "security-reviewer", "typescript-reviewer"]
    },
    "planner": {
      "label": "플래너",
      "voice": "Ryan",
      "agents": ["architect", "plan", "planner"]
    },
    "builder": {
      "label": "빌더",
      "voice": "Aiden",
      "agents": ["claude", "general-purpose", "build-error-resolver"]
    },
    "explorer": {
      "label": "탐색기",
      "voice": "Dylan",
      "agents": ["Explore", "code-explorer", "gitnexus-exploring"]
    }
  }
}
코드 변경 없이 JSON만 편집하면 에이전트 타입 → 음성 매핑이 즉시 적용됩니다. 새 에이전트 타입은 기존 카테고리 agents 배열에 추가하거나, 새 카테고리를 만들면 됩니다.

4실전 예시 — 페르소나가 부여된 팀 구성

예시

코드 리뷰 팀 (아키텍트 + 보안 + 성능)

// 팀 생성
TeamCreate({ team_name: "review-team" });

// 각 에이전트에 명확한 페르소나 부여
Agent({
  subagent_type: "architect",       // .claude/agents/architect.md 페르소나
  name: "agent-arch",
  model: "sonnet",
  prompt: `당신은 시스템 아키텍트입니다.
설계 원칙(SOLID, DRY), 확장성, 모듈 경계에 집중합니다.
src/의 구조적 문제를 분석하고 팀 리더에게 보고하세요.`
});

Agent({
  subagent_type: "security-reviewer", // .claude/agents/security-reviewer.md
  name: "agent-sec",
  model: "sonnet",
  prompt: `OWASP Top 10 기준으로 src/auth/를 분석하세요.
취약점 발견 시 심각도 분류 후 팀 리더에게 보고.`
});

Agent({
  subagent_type: "performance-optimizer", // .claude/agents/performance-optimizer.md
  name: "agent-perf",
  model: "sonnet",
  prompt: `핫패스(hot path) 코드의 알고리즘 복잡도와 메모리 사용을 분석하세요.
병목 지점을 팀 리더에게 보고.`
});

voice-map.json에 대응 목소리 추가

{
  "categories": {
    "reviewer": {
      "label": "리뷰어",
      "voice": "Eric",
      "agents": ["security-reviewer", "performance-optimizer", "architect"]
    }
  }
}

이제 각 에이전트가 완료되면:

agent-arch 완료 → "리뷰어입니다. 서비스 레이어 경계가 불명확합니다." agent-sec 완료 → "리뷰어입니다. JWT 검증 누락 — High severity." agent-perf 완료 → "리뷰어입니다. O(n²) 정렬 로직 발견했습니다."

주의사항

HMG 사내 환경: model: "sonnet"으로 고정하세요. Opus 모델은 사내 허브에서 지원되지 않습니다.
