TTS 파이프라인

Edge TTS → MLX 서버 → MLX subprocess → macOS say 4단계 폴백. Apple Silicon MLX 기반 Qwen3-TTS-0.6B 모델 상주.

다성 TTS

서브에이전트 타입(code-reviewer, planner 등)에 따라 Supertonic voice ID 자동 배정. voice-map.json만 편집하면 코드 변경 없이 확장 가능.

스킬 추천

세션 시작·프롬프트 입력 시 대화 transcript를 LLM으로 분석해 Claude Code 스킬 1개 음성 추천. 30분 쿨다운으로 반복 억제.

설계 원칙

nohup & disown 패턴으로 TTS를 hook timeout에서 완전 분리. silent fail 정책으로 Claude Code 응답을 절대 방해하지 않음.

voice-router.ts 로직 검증

코드 레벨 검증 결과 resolveVoice() 로직은 정상입니다. voice-map.json의 categories 배열을 순회해 agentType 포함 여부를 확인 후 voice를 반환합니다.

// src/voice-router.ts:31-38
export function resolveVoice(agentType: string, map: VoiceMap): string {
  for (const [category, agents] of Object.entries(map.categories)) {
    if (agents.includes(agentType)) {
      return map.voices[category] ?? map.voices.default ?? "F1";
    }
  }
  return map.voices.default ?? "F1";
}

🔴 HIGH 이슈 (4건)

HIGH  stop.sh — TEXT 쉘 인수 전달 → Command Injection 가능
📄 hooks/stop.sh:24  |  hooks/subagent-stop.sh:63 동일

nohup node ... hook "$TEXT"에서 Claude 응답 전체 텍스트를 쉘 인수로 전달합니다. $(...)나 백틱이 응답에 포함되면 쉘이 추가 실행을 시도합니다.

개선 방안 — stdin으로 전달

# 현재 (위험)
nohup node "$SCRIPT" hook "$TEXT" > /dev/null 2>&1 &

# 개선 — stdin 경유
echo "$TEXT" | nohup node "$SCRIPT" hook > /dev/null 2>&1 &

Node.js 쪽에서 process.stdin을 읽도록 수정 필요.

HIGH  speakEdge — 타임아웃 시 orphan 프로세스 + 임시 파일 누수
📄 src/player.ts:119-131

Promise.race로 10초 타임아웃이 발동할 때 python3 프로세스가 계속 실행되고, /tmp/siren_edge_*.mp3 파일이 정리되지 않아 누적됩니다.

async function speakEdge(text: string, voice: string, speed: number): Promise<void> {
  const outFile = `/tmp/siren_edge_${Date.now()}.mp3`;
  let proc: ReturnType<typeof spawn> | undefined;
  const edgePromise = new Promise<void>((resolve, reject) => {
    proc = spawn(MLX_PYTHON, ["-c", EDGE_SCRIPT, text, edgeVoice, outFile]);
    proc.on("close", (code) => code === 0 ? resolve() : reject());
    proc.on("error", reject);
  });
  try {
    await Promise.race([edgePromise, timeout(EDGE_TIMEOUT_MS)]);
  } catch {
    proc?.kill();          // orphan 프로세스 정리
    try { unlinkSync(outFile); } catch {}
    throw new Error("EdgeTTS 실패");
  }
  await spawnPromise("afplay", ["-r", String(speed), outFile]);
  try { unlinkSync(outFile); } catch {}
}
HIGH  EdgeTTS 온라인 우선 — 오프라인/사내망 환경에서 매 응답마다 10초 지연
📄 src/player.ts:196-219  |  CLAUDE.md 불일치

현재 speak()는 항상 Edge TTS를 먼저 시도합니다. HMG 사내망에서 차단되면 매 Claude 응답마다 10초를 기다린 뒤 폴백합니다. CLAUDE.md 아키텍처 다이어그램(HTTP → MLX → say)과도 불일치합니다.

개선 방안 옵션

  • .siren.json에 "preferOnline": false 옵션 추가
  • 네트워크 도달 가능 여부를 캐싱 (세션당 1회만 체크)
  • 환경변수 SIREN_OFFLINE=1로 Edge TTS 비활성화
HIGH  speakSupertonic — speed 파라미터 미전달
📄 src/player.ts:152-176
