Grafana 폴링 루프 추가 방법

asyncio.gather()에 코루틴 하나만 추가하면 됨. 패턴이 완전히 정형화되어 있어 확장이 매우 자연스러움. 
# tts_server/supervisor.py 에 추가할 함수 (새 파일로 분리도 가능)
async def grafana_alert_loop(
    shutdown: asyncio.Event,
    spool_dir: Path = SPOOL_DIR,
    poll_interval: float = 30.0,
) -> None:
    """Grafana Webhook 또는 API 폴링 — 알럿 감지 시 spool에 오디오 기록."""
    while not shutdown.is_set():
        try:
            # ... 알럿 체크 로직 ...
            pass
        except Exception as e:
            log.error(f"[GrafanaAlert] 오류: {e}")
        try:
            await asyncio.wait_for(shutdown.wait(), timeout=poll_interval)
        except asyncio.TimeoutError:
            pass  # 정상 타임아웃, 다음 폴링 진행

# supervisor.py : main() 내 gather에 추가
await asyncio.gather(
    player_loop(shutdown=shutdown),
    cleanup_loop(shutdown=shutdown),
    monitor_children(procs, shutdown=shutdown),
    grafana_alert_loop(shutdown=shutdown),   # ← 여기에 추가
)
  • shutdown 이벤트를 파라미터로 받는 패턴을 그대로 따름 (supervisor.py:49–51, 113–115, 129–131)
  • asyncio.wait_for(shutdown.wait(), timeout=interval)가 표준 대기 패턴 (supervisor.py:124–126)
  • supervisor 재시작 없이 루프 오류만으로 전체가 죽지 않게 try/except를 각 루프 내부에 배치

4. FastAPI 서버 Webhook 엔드포인트 추가

현재 엔드포인트

경로메서드역할

Webhook 엔드포인트 추가 방법

# tts_server/server.py 에 추가

class GrafanaAlertPayload(BaseModel):
    title: str = ""
    message: str = ""
    state: str = ""   # "alerting" | "ok" | "no_data"
    ruleName: str = ""

@app.post("/grafana/webhook", status_code=202)
async def grafana_webhook(payload: GrafanaAlertPayload):
    """Grafana Contact Point Webhook 수신 — 알럿 상태를 TTS로 변환."""
    if payload.state != "alerting":
        return {"status": "ignored", "state": payload.state}
    alert_text = f"그라파나 알럿. {payload.ruleName}. {payload.message}"
    # spool에 직접 기록하거나 /speak 내부 큐로 전달
    try:
        _work_queue.put_nowait((alert_text, "Sohee", "korean", 1.1, "침착하게 전달해주세요"))
        return {"status": "accepted"}
    except queue.Full:
        return JSONResponse({"status": "busy"}, status_code=429)
주의: /speak는 MLX 워커 큐(_work_queue, maxsize=5)로 전달하는 방식. Grafana webhook도 같은 큐를 쓰면 TTS 발화가 MLX 서버(7777)를 통함. 반면 spool 방식(speak_hook이 하는 방식)은 hook_voice 모듈에 의존하므로 server.py에서 직접 import하면 순환 의존 위험 있음.

7. 기존 아키텍처와 충돌 가능 부분

MLX 워커 큐 포화
_work_queue는 maxsize=5 (server.py:31). Grafana 알럿이 짧은 시간에 다수 발생하면 429가 쏟아짐. spool 방식(EdgeTTS)을 쓰면 이 문제 우회 가능.
spool 순서 보장
player_loop은 파일명의 타임스탬프 오름차순으로 재생(supervisor.py:62). Grafana 알럿이 spool에 들어가면 기존 Claude 응답 발화와 경합. 알럿에 높은 우선순위를 주려면 파일명 prefix 조정이 필요.
순환 의존 위험
tts_server/server.py에서 hook_voice.player를 import하면 순환 의존 가능성. Grafana webhook → spool 기록은 server.py 내에서 직접 Path("/tmp/tts-spool")에 파일 쓰거나, /speak 큐를 경유하는 방식으로 분리.
HMG SSL 우회
Grafana가 사내망에 있으면 httpx.AsyncClient(verify=False)를 써야 함 (llm_client.py:32 참조). 외부 Grafana Cloud라면 시스템 CA 정상 동작.
