name: feature-architect
description: 신규 기능의 아키텍처 분석 및 설계 전문가. 구현 전 의존성·인터페이스·영향 범위를 파악.

당신은 **시니어 소프트웨어 아키텍트**입니다.
코드를 직접 작성하지 않습니다. 분석하고 설계합니다.

## 역할
- 기존 코드베이스를 읽고 새 기능이 어디에 어떻게 들어가야 하는지 파악
- 인터페이스, 데이터 흐름, 의존성 변경 사항을 명확히 기술
- 구현자가 바로 코딩할 수 있는 수준의 청사진 제공

## 행동 규칙
- 파일을 직접 수정하지 않는다
- 추측하지 않는다 — 코드를 읽은 후 판단한다
- 설계 결정마다 이유를 한 줄로 적는다
- 완료 후 팀 리더에게 SendMessage로 설계 요약을 보낸다

- 완료 후 팀 리더에게 SendMessage로 변경 파일 목록을 보낸다

실전 — 팀 리더 프롬프트 예시

voice-persona에 "TTS 실패 시 Slack 알림" 기능을 추가한다고 가정합니다. 아래가 Claude Code에 입력하는 전체 프롬프트입니다.

사용자 입력 프롬프트

신규 기능 개발 요청

TTS 재생 실패(Edge TTS timeout, MLX 서버 503)가 발생했을 때
Slack webhook URL로 알림을 보내는 기능을 추가합니다.

설정 파일(.voice-persona.json)에 slackWebhookUrl 옵션을 추가하고,
player.ts의 폴백 체인 끝에서 모든 TTS가 실패했을 때만 알림을 전송합니다.

팀을 구성하여 진행합니다.

이 입력을 받은 Claude Code(팀 리더)가 실행하는 전체 코드입니다.

팀 리더 실행 코드 (Claude Code 내부)
// 1. 팀 생성
TeamCreate({ team_name: "slack-notify" });

// 2. 태스크 정의 (의존성 포함)
const t1 = TaskCreate({
  subject: "설계: Slack 알림 기능 아키텍처 분석",
  description: `
    기존 player.ts 폴백 체인 구조를 분석하고
    slackWebhookUrl 설정 추가 위치, 알림 트리거 지점,
    HTTP fetch 호출 방식을 설계하라.
    config.ts, player.ts를 반드시 읽을 것.
  `
});

const t2 = TaskCreate({
  subject: "구현: Slack 알림 기능",
  description: `
    아키텍트 설계를 받아 다음을 구현:
    1. VoicePersonaConfig에 slackWebhookUrl?: string 추가 (config.ts)
    2. player.ts 폴백 체인 끝에 sendSlackAlert() 추가
    3. npm run build 확인 필수
  `
});
TaskUpdate({ taskId: t2.id, addBlockedBy: [t1.id] }); // 설계 완료 후 구현

const t3 = TaskCreate({
  subject: "테스트: Slack 알림 단위 테스트",
  description: `
    tests/player.test.ts에 다음 케이스 추가:
    - slackWebhookUrl 설정 시 실패 후 fetch 호출 확인
    - slackWebhookUrl 미설정 시 fetch 미호출 확인
    - fetch 실패해도 TTS 전체 흐름에 영향 없음 확인
    npm test 전체 통과 필수.
  `
});
TaskUpdate({ taskId: t3.id, addBlockedBy: [t2.id] }); // 구현 완료 후 테스트

const t4 = TaskCreate({
  subject: "리뷰: 구현·테스트 코드 품질 검토",
  description: `
    변경된 config.ts, player.ts, tests/player.test.ts를 검토:
    - webhook URL 검증 없이 그대로 fetch하는지 (SSRF 위험)
    - 타입 안전성 (slackWebhookUrl?: string 옵셔널 처리)
    - fetch 타임아웃 처리 여부
  `
});
TaskUpdate({ taskId: t4.id, addBlockedBy: [t3.id] }); // 테스트 완료 후 리뷰

// 3. 에이전트 spawn — subagent_type = agents/ 파일명
Agent({
  subagent_type: "feature-architect",  // .claude/agents/feature-architect.md 적용
  name: "agent-arch",
  model: "sonnet",
  team_name: "slack-notify",
  prompt: `
    Task #${t1.id}를 수행합니다.

    ## 분석 대상
    - src/config.ts — VoicePersonaConfig 인터페이스, DEFAULTS
    - src/player.ts  — speakHook(), speakAgent(), 폴백 체인 구조

    ## 산출물
    1. slackWebhookUrl 필드를 config.ts 어디에 추가할지
    2. 알림을 보낼 정확한 위치 (함수명, 줄 번호대)
    3. fetch 호출 패턴 (fire-and-forget vs await)
    4. 타임아웃 처리 방법

    완료 후 팀 리더에게 설계 요약을 SendMessage로 보내고
    Task #${t1.id}를 completed로 업데이트하세요.
  `
});
