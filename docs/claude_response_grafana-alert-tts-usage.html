Grafana Alert → TTS 사용 방법

HMG 사내 Grafana 알럿을 폴링하여 LLM 분석 요약을 음성으로 발화하는 기능

1. 동작 원리

TTS Supervisor가 Grafana Alertmanager API를 주기적으로 폴링하여 알럿 상태 변화를 감지하고, LLM으로 원인·대응 방향을 요약한 뒤 TTS로 발화합니다.

GrafanaPoller (supervisor 내 asyncio Task) │ ├─ GET /api/alertmanager/grafana/api/v2/alerts (30초마다, verify=False) │ ↓ ├─ fingerprint 기반 상태 변화 감지 │ ├─ 신규 Firing → LLM 분석 (원인·대응 2~3문장) → TTS 발화 │ └─ Resolved → 규칙 기반 "{이름} 알럿이 해소됐습니다. N분 만에 복구됐습니다." │ ↓ └─ speak_hook() → /tmp/tts-spool/ → afplay 순차 재생
첫 번째 폴링 사이클은 스냅샷 수집만 수행하고 발화하지 않습니다 — supervisor 재시작 시 기존 알럿이 중복 발화되는 것을 방지합니다.

2. 설정 방법 필수

프로젝트 루트의 .voice-persona.json에 grafana 섹션을 추가합니다.

{
  "grafana": {
    "enabled": true,
    "url": "http://grafana.hmg-internal:3000",
    "token": "glsa_xxxxxxxxxxxxxxxx",
    "interval": 30,
    "alerts": [
      "Kafka Consumer Lag",
      "Spark Job Failed"
    ]
  }
}
키기본값설명
enabledfalse폴러 활성화 여부. true로 바꿔야 동작합니다.
url""Grafana 인스턴스 URL (예: http://grafana.hmg-internal:3000)
token""Grafana Service Account Token (glsa_로 시작)
interval30폴링 간격(초). 너무 짧으면 LLM 비용이 늘어납니다.
alerts[]감시할 alertname 목록. 빈 배열이면 아무것도 감지하지 않습니다.

Grafana Service Account Token 발급

  1. Grafana → Administration > Service accounts
  2. Add service account → Role: Viewer (읽기 전용으로 충분)
  3. Add service account token → 토큰 복사 (glsa_로 시작)
토큰을 .voice-persona.json에 평문 저장합니다. 해당 파일이 git에 커밋되지 않도록 .gitignore에 추가하세요.

3. 감시 알럿 관리 (CLI)

설정 파일을 직접 편집하는 대신 CLI로 감시 목록을 관리할 수 있습니다.

# 현재 감시 중인 알럿 목록 확인
python -m hook_voice grafana list

# 알럿 추가
python -m hook_voice grafana add "Kafka Consumer Lag"
python -m hook_voice grafana add "Spark Job Failed"

# 알럿 제거
python -m hook_voice grafana remove "Kafka Consumer Lag"
add / remove 후에는 반드시 TTS supervisor를 재시작해야 변경이 반영됩니다.
./server.sh restart

4. 처음 설정하는 경우 — 단계별 순서

1
Grafana token 발급
Grafana → Service accounts → 토큰 생성
2
.voice-persona.json 작성
enabled: true, url, token 입력
3
감시할 알럿 등록
python -m hook_voice grafana add "알럿명"
4
TTS supervisor 재시작
./server.sh restart
5
로그 확인
./server.sh logs 30 → [Grafana] 폴링 시작 메시지 확인

5. 발화 예시

Firing 알럿 (LLM 분석)

"Kafka Consumer Lag 알럿이 발생했습니다. Consumer group이 메시지 소비 속도를 따라가지 못하고 있습니다. 프로듀서 처리량을 확인하거나 파티션 수를 늘리는 방향을 검토하세요."

Resolved 알럿 (규칙 기반)

"Kafka Consumer Lag 알럿이 해소되었습니다. 12분 만에 복구됐습니다."

Burst (3개 초과 동시 변화)

"5개 알럿 상태가 변경됐습니다. 발생 3개, 해소 2개."

6. 에러 처리

상황동작
네트워크 타임아웃 / 연결 실패경고 로그 기록 후 다음 사이클에서 재시도. 발화 없음.
401 / 403 인증 실패"Grafana 인증에 실패했습니다. 토큰을 확인해 주세요." 1회 발화 후 폴러 비활성화.
LLM 분석 실패규칙 기반 폴백: "{알럿명} 알럿이 발생했습니다."
3개 초과 동시 알럿개별 분석 대신 묶음 요약 1회 발화.

7. 로그 확인

# 실시간 로그 스트리밍
./server.sh logs 50

# 주요 로그 패턴
# [Grafana] 폴링 시작 (interval=30s, alerts=['Kafka Consumer Lag'])
# [Grafana] 첫 폴링 완료 — snapshot 수집 (발화 없음)
# [Grafana] 폴링 실패: ConnectError   ← 네트워크 오류
# [Grafana] Grafana 인증 실패 (HTTP 401) — 폴러를 비활성화합니다.
