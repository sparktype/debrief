3. supervisor.py — 프로세스/태스크 관리

3-1. asyncio Task 구조

async def main():
    shutdown = asyncio.Event()

    # SIGTERM/SIGINT → shutdown.set()
    for sig in (signal.SIGTERM, signal.SIGINT):
        loop.add_signal_handler(sig, shutdown.set)

    # 자식 프로세스 기동
    uvicorn_proc   = _start_uvicorn()    # :7777 — FastAPI TTS 서버
    supertonic_proc = _start_supertonic() # :7788 — supertonic TTS 엔진

    # 3개 코루틴 동시 실행 (shutdown 이벤트로 공유 종료 제어)
    await asyncio.gather(
        player_loop(shutdown=shutdown),      # spool 파일 재생
        cleanup_loop(shutdown=shutdown),     # 30분 주기 정리
        monitor_children(procs, shutdown),   # 자식 프로세스 감시
    )

3-3. player_loop — /tmp/tts-spool/ 폴링 메커니즘

1
파일 탐색
spool.glob("*.wav") + glob("*.mp3") → 알파벳 정렬 (= 시간순, 파일명이 epoch_ms 시작)
2
속도 파싱
stem.rsplit("_", 1)[-1] — 마지막 _ 뒤 숫자 추출. "120" → "1.2"
3
재생 + PID 기록
asyncio.create_subprocess_exec("afplay", "-r", speed, file). PID → /tmp/tts-spool/.player.pid
4
종료 대기 (동시)
asyncio.wait([play_task, shutdown.wait()], FIRST_COMPLETED) — shutdown 시 afplay terminate → 2초 timeout → kill
5
파일 삭제
재생 완료 시 audio.unlink(missing_ok=True). 유휴 시 지수 백오프: min(0.3 × 1.5^idle, 2.0)초 대기

3-4. 자식 프로세스 종료 전략 (_graceful_shutdown)

async def _graceful_shutdown(procs):
    # 역순 종료: supertonic → uvicorn
    for proc in reversed(procs):
        proc.terminate()    # SIGTERM

    # 5초 데드라인 — 응답 없으면 SIGKILL
    deadline = loop.time() + 5.0
    for proc in procs:
        remaining = max(0.1, deadline - loop.time())
        try:
            await asyncio.wait_for(
                loop.run_in_executor(None, proc.wait),
                timeout=remaining,
            )
        except asyncio.TimeoutError:
            proc.kill()   # SIGKILL

4. 두 컴포넌트 간 상호작용

4-1. supervisor → uvicorn 관리 방식

supervisor는 uvicorn을 subprocess.Popen으로 자식 프로세스로 기동합니다. 직접 코루틴이나 스레드로 실행하는 것이 아니라 독립 OS 프로세스로 분리되므로, uvicorn이 크래시해도 supervisor 이벤트 루프가 영향받지 않습니다. monitor_children()이 1초마다 proc.poll()으로 생존을 확인하고, 비정상 종료 감지 시 shutdown.set()으로 전체 종료를 트리거합니다.

4-2. 파일시스템 큐를 통한 재생 파이프라인

5. 잠재적 문제점 및 개선 포인트

⚠️ 개별 자식 프로세스 재시작 없음 — All-or-Nothing 종료
uvicorn 또는 supertonic 중 하나만 크래시해도 monitor_children()이 shutdown.set() → 전체 supervisor 종료 → launchd 재시작을 유발합니다. 재시작 중 모델을 다시 로딩하는 시간(수십 초) 동안 TTS 서비스가 완전히 중단됩니다.

개선 방향: uvicorn/supertonic 개별 재시작 로직 추가. 예: max_restarts=3까지 재기동 시도 후 전체 종료.
🔴 work_queue maxsize=1 — 높은 429 발생 가능성
_work_queue = queue.Queue(maxsize=1)로 큐에 최대 1개만 허용합니다. 워커가 추론 중일 때(수 초 소요) 들어오는 모든 요청은 429가 됩니다. Claude Hook이 짧은 간격으로 여러 번 호출하는 상황에서 발화가 누락될 수 있습니다.

개선 방향: maxsize=3~5로 확장하거나, /speak를 spool 방식(파일 드롭)으로 전환하여 player_loop가 처리하도록 통일.
⚠️ speed 파싱 취약성 — rsplit("_", 1)
파일명 파싱 로직: stem.rsplit("_", 1) → 마지막 _ 뒤가 순수 숫자면 speed로 인식. 예: 1748261234567_ab3kx_120.wav → speed=1.2 (정상). 하지만 uid5 랜덤 부분이 12345 같은 순수 숫자로 끝나는 경우(낮은 확률이지만 가능), speed_tag 없이 enqueue된 파일은 잘못 파싱될 수 있습니다.

개선 방향: 파일명 형식을 {epoch}_spd{speed100}.ext처럼 speed 구분자를 명시적으로 접두사화.
⚠️ Supertonic HF_HUB_OFFLINE=0 — 사내망 SSL 실패 가능
_start_supertonic()에서 HF_HUB_OFFLINE=0으로 설정되어 있어 HuggingFace에 접근을 시도합니다. HMG 사내망의 SSL 인터셉트 프록시 환경에서 supertonic이 모델을 다운로드하거나 메타데이터를 확인할 때 SSL 오류가 발생할 수 있습니다.

개선 방향: 모델을 미리 캐시해두고 HF_HUB_OFFLINE=1로 전환하거나, REQUESTS_CA_BUNDLE 환경변수로 HMG CA 번들 지정.
ℹ️ _model_error_message — 스레드 안전성 미확보
_model_error_message는 str 타입 전역 변수로, 워커 스레드에서 쓰고 FastAPI 스레드에서 읽습니다. CPython GIL 덕분에 실제 데이터 손상은 없지만, 원칙적으로 threading.Lock이나 threading.Event에 메시지를 번들로 묶는 것이 더 안전합니다.
ℹ️ .player.pid 파일 — 재생 중 예외 시 미삭제 엣지 케이스
player_loop의 예외 핸들러에서 .player.pid 삭제를 시도하지만, 예외가 pid_file.unlink() 이전에 발생하면 잔여 파일이 남을 수 있습니다. 다만 기능에 영향을 주지는 않으며 다음 루프에서 덮어써집니다.
ℹ️ /tmp/tts-spool/ 재부팅 시 초기화
macOS 재부팅 또는 /tmp 정리 시 spool 디렉터리가 사라집니다. player_loop()가 시작 시 spool.mkdir(exist_ok=True)로 자동 생성하므로 기능 장애는 없지만, 재부팅 전 큐에 남아있던 미재생 파일은 소실됩니다.
