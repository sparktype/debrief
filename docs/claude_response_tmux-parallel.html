tmux pane이 생성되지 않은 이유 — 그리고 앞으로 tmux 기반으로 작업하는 법

1. 이번에 tmux pane이 생성되지 않은 근본 원인

핵심 오해: "팀으로 병렬 작업 = tmux pane이 생긴다"는 전제가 성립하지 않습니다.
Agent 도구와 tmux pane은 완전히 다른 레이어에서 동작합니다.

Agent 도구의 실제 동작 방식

이번에 사용한 dispatching-parallel-agents 스킬은 내부적으로 Claude Code의 Agent 도구를 호출합니다.

속성Agent 도구 (이번 방식)tmux pane (원하던 방식)
실행 위치Claude Code 내부 API 프로세스실제 터미널 셸 세션
가시성보이지 않음 — 백그라운드 API 호출화면에서 직접 확인 가능
권한 모델부모 세션에서 상속 또는 별도 설정일반 셸 권한 그대로
통신메시지 큐 (SendMessage 도구)tmux send-keys + 파일
생성 명령Agent(prompt=..., run_in_background=true)tmux split-window
결과 수신task-notification 이벤트직접 확인 / tail -f

Agent 도구는 Claude 모델 인스턴스를 API로 새로 띄우는 것이지, 터미널 프로세스를 생성하는 게 아닙니다. 따라서 tmux pane은 아무리 많은 에이전트를 배포해도 자동으로 생기지 않습니다.

이번 세션에서 실제 일어난 일

리드 에이전트 (이 세션)
  │
  ├─ Agent(shell-team, run_in_background=true)
  │     └─ 새 Claude API 호출 → 별도 프로세스 (터미널 없음)
  │           └─ 도구 실행 권한 없어 Bash 차단 → 실패
  │
  └─ Agent(ts-team, run_in_background=true)
        └─ 새 Claude API 호출 → 별도 프로세스 (터미널 없음)
              └─ 도구 실행 권한 없어 Bash 차단 → 실패

서브에이전트가 Bash를 차단당한 이유는 별도입니다 — Claude Code의 permission mode 설정과 관련이 있으며, worktree 환경에서 서브에이전트는 부모 세션의 권한을 그대로 상속받지 않습니다.

2. tmux pane 기반으로 병렬 작업하는 방법

tmux 기반 병렬 작업에는 두 가지 패턴이 있습니다.

패턴언제 쓰나핵심 도구
A. Shell 스크립트 병렬화빌드·테스트·배포 등 쉘 작업tmux split-window + send-keys
B. Claude Code 다중 인스턴스AI 에이전트 팀 구성tmux + claude CLI 각 pane

패턴 A — Shell 병렬 작업 (빌드·테스트·서버 등)

Claude Code가 Bash 도구로 tmux 명령을 직접 실행해 pane을 만들고 명령을 전송합니다.

# 1. 세션 생성 (이미 있으면 attach)
tmux new-session -d -s work -x 220 -y 50

# 2. 수평 분할 → 두 pane
tmux split-window -h -t work

# 3. 각 pane에 명령 전송
tmux send-keys -t work:0.0 "npm test --watch" Enter      # 좌측 pane
tmux send-keys -t work:0.1 "python -m pytest -v" Enter   # 우측 pane

# 4. 확인
tmux list-panes -t work

결과를 파일로 캡처해 리드 에이전트가 읽을 수도 있습니다:

# 각 pane 출력을 로그 파일로 리디렉션
tmux send-keys -t work:0.0 "bash shell-team.sh 2>&1 | tee /tmp/shell-team.log" Enter
tmux send-keys -t work:0.1 "bash ts-team.sh 2>&1 | tee /tmp/ts-team.log" Enter

# 완료 대기 (Monitor 도구 또는 until 루프)
until grep -q "DONE\|ERROR" /tmp/shell-team.log /tmp/ts-team.log 2>/dev/null; do sleep 2; done

패턴 B — Claude Code 다중 인스턴스 (AI 팀)

각 tmux pane에 claude CLI를 실행시켜 독립적인 AI 에이전트로 만드는 방식입니다.

이 방식이 tmux pane이 실제로 생기면서 AI가 병렬 작업하는 구조입니다. 
# 리드 에이전트가 Bash 도구로 실행하는 예시

# 세션 생성
tmux new-session -d -s ai-team -x 250 -y 60

# Shell 팀 pane (pane 0)
tmux send-keys -t ai-team:0.0 "cd /path/to/project && claude --print 'Shell 팀 태스크: D1·C1·C3·C2·S2·S1 수행. 파일 범위: server.sh, tts_server/*.sh'" Enter

# TypeScript 팀 pane 추가 (수평 분할)
tmux split-window -h -t ai-team
tmux send-keys -t ai-team:0.1 "cd /path/to/project && claude --print 'TS 팀 태스크: Q1·Q2·L1·L2·L3·S3·Q3·Q4 수행. 파일 범위: src/*.ts'" Enter

# 두 pane 모니터링
tmux attach -t ai-team

하지만 이 방식은 Claude Code가 이미 tmux 세션 안에서 실행 중일 때 더 자연스럽게 동작합니다.

3. 권장 설정 — Claude Code를 처음부터 tmux 안에서 실행

tmux pane 기반 협업이 가능하려면 리드 에이전트 자신도 tmux 세션 안에 있어야 합니다.

# ~/.zshrc 또는 ~/.bashrc에 추가 (자동으로 tmux 안에서 시작)
if command -v tmux &>/dev/null && [[ -z "$TMUX" ]]; then
  tmux new-session -A -s main
fi

# 또는 alias 설정
alias cc='tmux new-session -A -s claude && claude'

이렇게 하면 claude를 실행할 때 항상 tmux 세션 안에 있고, 서브 pane 생성이 자연스럽게 가능합니다.

tmux 레이아웃 추천 (3-pane 팀 작업)

┌─────────────────────────────┬─────────────────────────────┐
│                             │                             │
│   리드 에이전트 (claude)    │     Shell 팀 작업           │
│   - 조율·검토·통합          │     (server.sh, *.sh)       │
│                             │                             │
│                             ├─────────────────────────────┤
│                             │                             │
│                             │   TypeScript 팀 작업        │
│                             │   (src/*.ts, npm test)      │
│                             │                             │
└─────────────────────────────┴─────────────────────────────┘
# 위 레이아웃 만들기
tmux new-session -d -s team -x 240 -y 60
tmux split-window -h -t team          # 좌우 분할
tmux split-window -v -t team:0.1      # 우측 상하 분할
# 결과: pane 0 (좌) = 리드, pane 1 (우상) = Shell 팀, pane 2 (우하) = TS 팀

스킬tmux pane 생성 여부설명

현실적인 권장 방법:
다음번 팀 병렬 작업 시 "tmux pane 방식으로 진행해 주세요"라고 명시하면, 리드 에이전트가 Bash 도구로 tmux split-window를 실행해 각 팀 작업용 pane을 직접 생성하고 명령을 전송할 수 있습니다.

단, tmux가 이미 실행 중이어야 하고 (echo $TMUX로 확인), claude도 그 tmux 세션 안에서 실행 중이어야 합니다.
