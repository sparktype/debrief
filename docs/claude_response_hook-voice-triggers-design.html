2. Bash 명령 분류 패턴

이유: 한 정규식 집합을 PreToolUse·PostToolUse 양쪽에서 공유해야 메시지 일관성이 보장됨. 별도 유틸 함수 classifyBashCommand(cmd)로 분리 → index.ts 내부에 정의.

카테고리정규식 (case-insensitive)매칭 예시
TEST
/^(npm\s+(run\s+)?test|npx\s+vitest|bun\s+test|pytest|cargo\s+test|go\s+test|yarn\s+test|jest)\b/i
 npm test, npx vitest run, pytest, cargo test
BUILD
/^(npm\s+run\s+(build|dev|compile)|tsc\b|cargo\s+build|go\s+build|bun\s+build|make\b|gradle\b|mvn\b)/i
 npm run build, tsc, cargo build, make
INSTALL
/^(npm\s+(install|i)\b|pip\s+install|cargo\s+add|bun\s+install|yarn\s+add|brew\s+install|apt\s+install)/i
 npm install, pip install, brew install
GIT
/^git\b/i
 git commit, git push, git diff
DOCKER
/^(docker|docker-compose|kubectl)\b/i
 docker build, kubectl apply
DEFAULT (위 패턴에 모두 미해당) ls, cat, curl, sed ... 
type BashCategory = "TEST" | "BUILD" | "INSTALL" | "GIT" | "DOCKER" | "DEFAULT";

function classifyBashCommand(cmd: string): BashCategory {
  if (/^(npm\s+(run\s+)?test|npx\s+vitest|bun\s+test|pytest|cargo\s+test|go\s+test|yarn\s+test|jest)\b/i.test(cmd)) return "TEST";
  if (/^(npm\s+run\s+(build|dev|compile)|tsc\b|cargo\s+build|go\s+build|bun\s+build|make\b|gradle\b|mvn\b)/i.test(cmd)) return "BUILD";
  if (/^(npm\s+(install|i)\b|pip\s+install|cargo\s+add|bun\s+install|yarn\s+add|brew\s+install|apt\s+install)/i.test(cmd)) return "INSTALL";
  if (/^git\b/i.test(cmd)) return "GIT";
  if (/^(docker|docker-compose|kubectl)\b/i.test(cmd)) return "DOCKER";
  return "DEFAULT";
}

3. 테스트 결과 파싱 정규식

이유: vitest / pytest / cargo test 세 도구 모두 "N passed" / "N failed" 형식을 공유하므로 단일 정규식으로 통합 처리 가능. cargo만 별도 패턴 추가 보완.

도구대표 출력 예시파싱 정규식
vitest Tests 5 passed (5)
Tests 3 failed | 2 passed (5)		 통과: /(\d+)\s+passed/i
실패: /(\d+)\s+failed/i
pytest 5 passed, 1 failed in 0.42s 동일 패턴 적용
cargo test test result: ok. 5 passed; 0 failed; 전용: /test result:\s*(ok|FAILED)\.\s*(\d+) passed;\s*(\d+) failed/
(폴백으로 공통 패턴도 적용) 
interface TestResult { passed: number; failed: number; }

function parseTestOutput(output: string): TestResult | null {
  // cargo test 전용 — 더 구체적인 패턴 먼저
  const cargo = /test result:\s*(ok|FAILED)\.\s*(\d+) passed;\s*(\d+) failed/.exec(output);
  if (cargo) return { passed: parseInt(cargo[2]), failed: parseInt(cargo[3]) };

  // vitest / pytest 공통
  const passedM = /(\d+)\s+passed/i.exec(output);
  const failedM = /(\d+)\s+failed/i.exec(output);
  if (!passedM && !failedM) return null;
  return {
    passed: passedM ? parseInt(passedM[1]) : 0,
    failed: failedM ? parseInt(failedM[1]) : 0,
  };
}

4. 쉘 스크립트 3종 전체 코드

이유: 기존 stop.sh의 nohup ... & disown $!; exit 0 패턴을 그대로 따른다. nohup 내에서 stdin이 파이프(TTY 아님)이므로 자식 node 프로세스가 부모 fd를 상속해 JSON을 정상 수신함.

hooks/pre-tool-bash.sh

#!/usr/bin/env bash
# Claude Code PreToolUse(Bash) hook — Bash 실행 직전 TTS 알림
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
nohup node "$SCRIPT_DIR/../dist/index.js" pre-tool-bash > /dev/null 2>&1 &
disown $!; exit 0

hooks/post-tool-bash.sh

#!/usr/bin/env bash
# Claude Code PostToolUse(Bash) hook — Bash 명령 완료 시 결과 TTS 알림
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
nohup node "$SCRIPT_DIR/../dist/index.js" post-tool-bash > /dev/null 2>&1 &
disown $!; exit 0

hooks/notification.sh

#!/usr/bin/env bash
# Claude Code Notification hook — 알림 메시지 TTS 발화
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
nohup node "$SCRIPT_DIR/../dist/index.js" notification > /dev/null 2>&1 &
disown $!; exit 0

5. src/index.ts 삽입 위치

현재 index.ts 구조 (라인 기준): 62–76 : if (argv[2] === "hook") { ... process.exit(0) } 78–100 : if (argv[2] === "subagent-stop") { ... process.exit(0) } 102–122 : if (argv[2] === "hook-suggest") { ... process.exit(0) } ──────────────────────────────────────────────────── ← 124번 줄부터 MCP 서버 모드 시작 ▶ 삽입 위치: 122번 줄 process.exit(0) 직후, 124번 줄 // ── MCP 서버 모드 직전 ▶ 헬퍼 함수 classifyBashCommand(), parseTestOutput() 는 extractAgentTypeFromTranscript() 함수(37–60번 줄) 블록 바로 아래에 추가

삽입 코드 골격

// classifyBashCommand(), parseTestOutput() 함수는 60번 줄 이후 삽입

// ── pre-tool-bash CLI 모드 ─────────────────────────────────
if (process.argv[2] === "pre-tool-bash") {
  if (!config.speakPreTool) process.exit(0);
  const raw = await readStdin();
  try {
    const data = JSON.parse(raw) as Record;
    const input = data.tool_input as Record | undefined;
    const cmd = String(input?.command ?? "").trim();
    if (cmd) {
      const cat = classifyBashCommand(cmd);
      const msg = PRE_TOOL_MSG[cat];          // 발화 메시지 맵 참조
      await speakHook(msg, config.voice, config.ttsSpeed).catch(() => {});
    }
  } catch { /* 무시 */ }
  process.exit(0);
}

// ── post-tool-bash CLI 모드 ────────────────────────────────
if (process.argv[2] === "post-tool-bash") {
  if (!config.speakPostTool) process.exit(0);
  const raw = await readStdin();
  try {
    const data    = JSON.parse(raw) as Record;
    const input   = data.tool_input   as Record | undefined;
    const resp    = data.tool_response as Record | undefined;
    const cmd     = String(input?.command ?? "").trim();
    const output  = String(resp?.output  ?? "");
    const exitCode = typeof resp?.exit_code === "number" ? resp.exit_code : null;
    const failed  = exitCode !== null ? exitCode !== 0 : String(resp?.error ?? "").length > 0;
    const cat     = classifyBashCommand(cmd);
    const msg     = buildPostToolMsg(cat, failed, output); // 메시지 생성 함수
    await speakHook(msg, config.voice, config.ttsSpeed).catch(() => {});
  } catch { /* 무시 */ }
  process.exit(0);
}

// ── notification CLI 모드 ──────────────────────────────────
if (process.argv[2] === "notification") {
  if (!config.speakNotification) process.exit(0);
  const raw = await readStdin();
  try {
    const data = JSON.parse(raw) as Record;
    const msg  = String(data.message ?? "").trim();
    if (msg) {
      await speak(msg, config.voice, config.ttsSpeed, config.ttsInstruct).catch(() => {});
    }
  } catch { /* 무시 */ }
  process.exit(0);
}

Notification

별도 문구 없음. data.message 값을 그대로 발화한다. 이유: Notification 메시지는 Claude Code가 이미 사람이 읽을 수 있는 짧은 문장으로 생성하므로 LLM 요약 불필요.

8. 전체 실행 흐름 (추가분)

Bash 명령 실행 직전 → PreToolUse hook (hooks/pre-tool-bash.sh) → node dist/index.js pre-tool-bash [stdin: PreToolUse JSON] → config.speakPreTool 체크 → false면 즉시 exit → classifyBashCommand(tool_input.command) → PRE_TOOL_MSG[category] 조회 → speakHook(msg) → EdgeTTS MP3 → /tmp/tts-spool/ → 즉시 반환 Bash 명령 완료 → PostToolUse hook (hooks/post-tool-bash.sh) → node dist/index.js post-tool-bash [stdin: PostToolUse JSON] → config.speakPostTool 체크 → classifyBashCommand(tool_input.command) → exit_code / error 필드로 성공 여부 판정 → category === TEST ? parseTestOutput(tool_response.output) : skip → buildPostToolMsg(cat, failed, output) → speakHook(msg) → EdgeTTS MP3 → /tmp/tts-spool/ → 즉시 반환 Claude Code 알림 발생 → Notification hook (hooks/notification.sh) → node dist/index.js notification [stdin: Notification JSON] → config.speakNotification 체크 → data.message 직접 speak() [withTTSLock 경로 — 짧은 텍스트] → 즉시 반환

9. .claude/settings.json 등록 패턴

server.sh install 이 자동 등록하므로, 스크립트에 아래 항목을 추가해야 함. 

{
  "hooks": {
    "PreToolUse": [{
      "matcher": "Bash",
      "hooks": [{"type": "command", "command": "<PROJECT>/hooks/pre-tool-bash.sh", "timeout": 10}]
    }],
    "PostToolUse": [{
      "matcher": "Bash",
      "hooks": [{"type": "command", "command": "<PROJECT>/hooks/post-tool-bash.sh", "timeout": 10}]
    }],
    "Notification": [{
      "matcher": "",
      "hooks": [{"type": "command", "command": "<PROJECT>/hooks/notification.sh", "timeout": 10}]
    }]
  }
}

※ PreToolUse timeout을 10초(Stop의 15초보다 짧게)로 설정하는 이유: Pre훅은 도구 실행을 블로킹하므로 최대한 짧아야 함. nohup + disown 구조로 실제 node 프로세스는 즉시 백그라운드로 넘어가므로 스크립트 자체는 수십 ms 내 exit 0.
