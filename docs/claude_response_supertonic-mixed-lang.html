Supertonic 한영 혼합 발음 분석

1. 핵심 발견사항

supertonic-3는 다국어(31개 언어) 모델이다.
config.py에서 multilingual: True로 명시되어 있고, "na"라는 특수 폴백 코드가 존재한다. lang을 지정하지 않으면 multilingual 모델은 자동으로 "na"를 사용한다.
현재 코드에서 lang 필드를 전혀 보내지 않는다.
speakSupertonic()의 요청 body에 lang이 없으므로 서버는 기본값 "na"로 처리한다. 이는 "모델이 알아서 언어를 감지해라"는 의미지만, 혼합 문장에서 영문을 한국어 발음으로 읽거나 반대 현상이 발생할 수 있다.

2. lang 파라미터 동작 방식

lang 값 동작 max_chunk_length 혼합 문장 적합성
"ko" 한국어 음소 처리, <ko>...</ko> 토큰 삽입 120자 (짧음) 부적합 영문 단어를 한국어 발음으로 읽음
"en" 영어 음소 처리, <en>...</en> 토큰 삽입 300자 부적합 한글이 영어 발음 체계로 처리됨
"na" (현재) <na>...</na> 폴백 토큰 — 모델이 자동 감지 300자 보통 모델 훈련 품질에 의존, 불규칙함
구간별 지정 (배치) 언어 전환 시점에 각각 올바른 토큰 삽입 각 구간 적용 최적 각 언어가 올바른 음소 체계 사용

3. 적용 가능한 접근법

접근법 A — 기술 용어 발음 사전 (단기, 즉시 적용 가능)

MLX TTS 서버의 _TECH_PHONETICS 패턴과 동일한 방식을 Node.js 쪽에 적용. 영문 기술 용어를 한국어 발음 표기로 치환한 뒤 lang="ko"로 전송.

장점

  • 서버 변경 없음
  • 즉시 적용 가능
  • 발음 예측 가능

단점

  • 사전에 없는 단어는 여전히 부자연스럽다
  • 고유명사·신조어 대응 불가
// player.ts 또는 voice-router.ts에 추가
const TECH_PHONETICS: Record = {
  "TypeScript": "타입스크립트",
  "React":      "리액트",
  "fetch":      "패치",
  "TTS":        "티티에스",
  "MCP":        "엠씨피",
  "API":        "에이피아이",
  "PR":         "피알",
  "CI":         "씨아이",
  // ... 확장 가능
};

function applyPhonetics(text: string): string {
  return Object.entries(TECH_PHONETICS).reduce(
    (t, [eng, kor]) => t.replace(new RegExp(`\\b${eng}\\b`, "gi"), kor),
    text
  );
}

접근법 B — 언어 구간 분할 + /v1/tts/batch (중기, 고품질)

텍스트를 한글/영어 구간으로 분리 → 배치 API로 각 구간에 올바른 lang 지정 → base64 WAV를 클라이언트에서 이어붙임. 각 언어가 올바른 음소 체계를 사용하므로 가장 자연스럽다.
"리뷰어입니다. TypeScript 코드 3건 수정"
→
구간 분할
→
[ko] "리뷰어입니다. "
[en] "TypeScript"
[ko] " 코드 3건 수정"
→
WAV 이어붙임
type LangSegment = { text: string; lang: "ko" | "en" };

function splitByLanguage(text: string): LangSegment[] {
  // 한글이 포함된 구간 = ko, 그 외 = en
  const segments: LangSegment[] = [];
  let cur = "";
  let curLang: "ko" | "en" | null = null;

  for (const ch of text) {
    const isKo = /[가-힣ㄱ-ㅎㅏ-ㅣ]/.test(ch);
    const lang: "ko" | "en" = isKo ? "ko" : "en";
    if (lang !== curLang) {
      if (cur.trim()) segments.push({ text: cur, lang: curLang! });
      cur = ch;
      curLang = lang;
    } else {
      cur += ch;
    }
  }
  if (cur.trim()) segments.push({ text: cur, lang: curLang! });
  return segments;
}

async function speakSupertonicMixed(
  text: string, voice: string, port: number, speed: number
): Promise {
  const segments = splitByLanguage(text);

  // 구간이 1개면 기존 방식
  if (segments.length === 1) {
    return speakSupertonic(text, voice, port, speed);
  }

  // 배치 요청
  const items = segments.map(s => ({
    text: s.text,
    voice,
    lang: s.lang,
    speed,
  }));
  const res = await fetch(`http://localhost:${port}/v1/tts/batch`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ items, response_format: "wav" }),
  });
  if (!res.ok) throw new Error(`Supertonic batch 오류: ${res.status}`);

  const { items: results } = await res.json() as { items: { audio_base64: string }[] };
  // base64 WAV 이어붙이기 (헤더는 첫 번째만, 이후는 data chunk만)
  const bufs = results.map(r => Buffer.from(r.audio_base64, "base64"));
  const merged = mergeWavBuffers(bufs);

  const outFile = `/tmp/siren_supertonic_${Date.now()}.wav`;
  writeFileSync(outFile, merged);
  await spawnPromise("afplay", ["-r", String(speed), outFile]);
  unlinkSync(outFile);
}
WAV 이어붙이기 주의: 각 배치 항목은 독립적인 WAV 파일(헤더 포함)이므로, 단순 Buffer.concat은 중간 헤더가 노이즈로 들린다. 첫 번째 WAV 헤더를 재사용하고 나머지는 PCM 데이터만 추출해야 한다 (mergeWavBuffers 구현 필요). 또는 ffmpeg -i concat:a.wav:b.wav -c copy out.wav를 사용하면 간단하다.

장점

  • 각 구간이 정확한 음소 체계 사용
  • supertonic-3 본연의 다국어 능력 활용
  • 사전 관리 불필요

단점

  • 구간 경계에서 운율이 끊길 수 있음
  • WAV 이어붙이기 구현 필요
  • 요청 수 증가 (배치 1회 = 동기 처리)

접근법 C — lang="na" 유지 + 영문 스페이싱 개선 (단기, 최소 변경)

현재 기본값("na")을 유지하되, 영문 단어 사이 공백을 확보해 모델이 단어 경계를 명확히 인식하도록 정규화. 대소문자 혼용 카멜케이스를 분리해 추가 힌트를 줌. 
function normalizeForSupertonicNa(text: string): string {
  return text
    // 카멜케이스 분리: "TypeScript" → "Type Script"
    .replace(/([a-z])([A-Z])/g, "$1 $2")
    // 한글+영문 경계에 공백 확보: "코드TypeScript" → "코드 TypeScript"
    .replace(/([가-힣])([A-Za-z])/g, "$1 $2")
    .replace(/([A-Za-z])([가-힣])/g, "$1 $2")
    // 연속 공백 정리
    .replace(/\s+/g, " ")
    .trim();
}

4. 권장 적용 순서

단계 방법 난이도 품질 향상
1단계 즉시 접근법 C — 경계 공백 정규화 + lang: "na" 명시 낮음 약간 개선
2단계 단기 접근법 A — 기술 용어 사전 치환 + lang: "ko" 낮음 주요 용어 개선
3단계 중기 접근법 B — 배치 API + WAV 병합 중간 최대 개선
Supertonic 서버가 아직 기동 중이 아닙니다. 모델 다운로드 완료 후 실제 혼합 문장 테스트를 해봐야 "na" 모드의 실제 품질을 알 수 있습니다. "na"만으로 충분히 자연스러우면 1단계만으로 끝낼 수 있고, 영어 단어 발음이 어색하다면 2→3단계로 진행합니다.

5. 현재 코드에서 가장 빠른 개선 포인트

src/player.ts의 speakSupertonic()에서 요청 body에 lang: "na"를 추가하고, 텍스트를 보내기 전에 경계 공백 정규화를 적용하면 됩니다. 배치 API 접근은 Supertonic 서버 동작 확인 후 품질 평가를 보고 결정하는 것을 권장합니다.
