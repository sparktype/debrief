Claude Code Hook 전체 분석 — Voice 트리거 설계

7개 훅 이벤트의 페이로드·타이밍 분석과 voice-persona 연동 신규 트리거 권고안

현황 매트릭스

훅 발화 시점 stdin 주요 데이터 현재 voice 구현 신규 기회
Stop Claude 응답 완료 last_assistant_message, transcript_path 구현됨 —
SubagentStop 서브에이전트 완료 transcript_path, last_assistant_message 구현됨 —
UserPromptSubmit 사용자 메시지 전송 prompt (사용자 입력 텍스트) 스킬 추천 키워드 감지 반응
SessionStart 새 세션 시작 — 스킬 추천 브리핑 모드
PreToolUse 도구 실행 직전 tool_name, tool_input (도구별 파라미터) 경고문만 (비voice) 착수 알림 (고우선순위)
PostToolUse 도구 실행 직후 tool_name, tool_input, tool_response (출력+exitCode) GitNexus만 (비voice) 결과 낭독 (고우선순위)
Notification Claude가 알림 전송 시 title, message 미구현 알림 음성 낭독

① Stop — 응답 완료

Stop 구현 완료
발화 시점: Claude가 한 턴의 응답을 마쳤을 때
stdin: JSON — last_assistant_message, transcript_path
제어 가능: 실행 후 알림만 (블로킹 불가)
✅
항상 — 마지막 응답 텍스트 추출
"[LLM 요약 또는 규칙 기반 폴백]" (기본 voice)
현재 구현: Edge TTS → Supertonic → MLX → say 폴백 체인
개선 여지: 응답 길이·내용 유형(코드 변경 / 설명 / 질문)을 분류해 유형별 요약 전략을 달리하면 더 자연스럽습니다.

② SubagentStop — 서브에이전트 완료

SubagentStop 구현 완료
발화 시점: Agent 툴로 spawn된 에이전트가 작업 종료 시
stdin: JSON — transcript_path (JSONL 역방향 파싱으로 subagent_type 추출)
✅
subagent_type → voice-map.json → 카테고리 voice
"[역할]입니다. [25자 한 줄 요약]" (역할별 목소리)
리뷰어=Eric, 플래너=M1, 빌더=M4, 테스터=F2, 탐색기=F3

③ UserPromptSubmit — 사용자 입력 전송

UserPromptSubmit 스킬 추천 구현 — 확장 가능
발화 시점: 사용자가 Enter를 누른 직후, Claude가 처리 시작 전
stdin: JSON — prompt (사용자 입력 원문)
제어 가능: 출력문을 Claude 컨텍스트에 주입 가능

현재

✅
최근 transcript 분석 → 적합한 스킬 추천
"[스킬명] 사용을 권장합니다."

신규 트리거 추천

🆕
prompt에 "팀" / "에이전트" / "병렬" 키워드 포함
"팀 작업을 시작합니다. 모델은 Sonnet만 사용합니다."
HMG 제약 조건을 사용자에게 remind 중간
🆕
prompt 길이 > 500자 (복잡한 작업 감지)
"복잡한 작업입니다. 잠시 분석 중입니다."
사용자가 자리를 뜨기 전에 인지시킴 낮음

④ SessionStart — 세션 시작

SessionStart 스킬 추천 구현 — 확장 가능
발화 시점: Claude Code가 새 세션을 열었을 때 (최초 1회)
stdin: 거의 비어 있음 (세션 메타 없음)

신규 트리거 추천

🆕
마지막 Stop 이후 시간이 1시간 이상 경과
"N시간 만에 돌아왔군요. 지난 작업을 이어갑니다."
구현: stat ~/.claude/last_stop_ts 파일로 경과 시간 계산 낮음

⑤ PreToolUse — 도구 실행 직전 ★ 핵심 신규 기회

PreToolUse Voice 미연결 — 신규 구현 권고
발화 시점: Claude가 도구를 실행하려는 순간 (실행 전)
stdin: JSON — tool_name, tool_input (도구별 파라미터)
블로킹 가능: exit 2 + stdout에 사유 → 도구 실행 취소
matcher: 도구 이름 또는 정규식으로 필터링
stdin 페이로드 예시 (Bash)
{
  "tool_name": "Bash",
  "tool_input": {
    "command": "npm run build",
    "description": "TypeScript 빌드"
  }
}

신규 트리거 추천

🔨
Bash + command 에 npm run build / tsc / cargo build
"빌드를 시작합니다."
builder 카테고리 voice — 자리 비워도 됨을 알림 높음
🧪
Bash + command 에 npm test / pytest / cargo test / go test
"테스트를 실행합니다."
tester 카테고리 voice — 완료까지 자리 비울 수 있음 높음
📦
Bash + command 에 npm install / npm ci / pip install / uv sync
"패키지를 설치합니다. 시간이 걸릴 수 있습니다."
기본 voice — 장시간 작업 예고 중간
🚀
Bash + command 에 git push
"원격 저장소에 푸시합니다."
현재 텍스트 경고만 — voice로 전환 권고 중간
🤖
Agent 도구 실행 (tool_name = "Agent")
"에이전트를 파견합니다. [description]"
팀 작업 착수를 음성으로 알림 — description 필드 활용 중간
⚠️
Bash + command 에 rm -rf / DROP TABLE / git reset --hard
"주의: 되돌릴 수 없는 삭제 작업입니다."
경고 voice — 사용자 주의 환기. exit 0이면 실행 허용 높음

⑥ PostToolUse — 도구 실행 직후 ★ 핵심 신규 기회

PostToolUse Voice 미연결 — 신규 구현 권고
발화 시점: 도구 실행 완료 직후 (Claude가 결과를 보기 전)
stdin: JSON — tool_name, tool_input, tool_response (출력+exitCode)
블로킹: 불가 (이미 실행됨)
stdin 페이로드 예시 (Bash — 테스트 실패)
{
  "tool_name": "Bash",
  "tool_input": { "command": "npm test" },
  "tool_response": {
    "output": "Tests: 3 failed, 72 passed\nFailed: player.test.ts > ...",
    "exitCode": 1
  }
}

신규 트리거 추천

❌
Bash + exitCode != 0 (명령 실패)
"명령 실패: [앞 30자]. 에러를 확인하세요."
가장 높은 가치 — 자리 비운 사이 실패 즉시 인지 가능. command에서 의미 있는 서술어만 추출 (npm, git, python 등) 높음
🧪
Bash + npm test / pytest 실행 후 output 파싱
"테스트 N개 통과, M개 실패." 또는 "전체 N개 통과."
output에서 (\d+) passed, (\d+) failed 정규식으로 추출. 실패 0이면 성공 voice, 1 이상이면 경고 voice 높음
🏗️
Bash + npm run build / tsc 성공 (exitCode = 0)
"빌드 완료."
PreToolUse "빌드 시작"과 쌍을 이루는 완료 알림 높음
📝
Bash + git commit 성공
"커밋 완료." (commit message 앞 20자 포함 가능)
output에서 commit hash + message 추출 중간
✍️
Write 도구 완료 (신규 파일 생성)
"[파일명] 작성 완료."
tool_input.file_path에서 파일명만 추출. Edit(수정)은 너무 잦아 생략 권고 낮음

⑦ Notification — Claude 알림

Notification 미구현 — 검토 필요
발화 시점: Claude가 사용자에게 데스크톱 알림을 보낼 때
stdin: JSON — title, message
stdin 페이로드 예시
{
  "title": "작업 완료",
  "message": "빌드 및 테스트 완료. 검토가 필요합니다."
}
🔔
모든 Notification
"[message 원문 낭독]"
화면을 보지 않아도 알림 내용을 즉시 인지. 가장 자연스러운 voice 연동 지점. 높음
설정 방법 (확인 필요):
~/.claude/settings.json의 hooks.Notification에 등록하면 됩니다. Stop과 동일한 방식으로 voice-persona의 node dist/index.js notification을 호출하면 됩니다.

구현 설계 — PostToolUse Bash 핸들러

우선순위 1순위인 PostToolUse Bash(빌드·테스트 결과 알림)의 구현 스케치입니다.

hooks/post-tool-bash.sh (신규)
#!/usr/bin/env bash
# PostToolUse Bash hook — 빌드·테스트 결과를 voice로 알림
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
nohup node "$SCRIPT_DIR/../dist/index.js" post-tool-bash > /dev/null 2>&1 &
disown $!; exit 0
src/index.ts — post-tool-bash 분기 (신규 추가)
if (process.argv[2] === "post-tool-bash") {
  const raw = await readStdin();
  try {
    const data = JSON.parse(raw) as {
      tool_name: string;
      tool_input: { command?: string };
      tool_response: { output?: string; exitCode?: number };
    };
    const cmd = data.tool_input.command ?? "";
    const out = data.tool_response.output ?? "";
    const code = data.tool_response.exitCode ?? 0;

    // 빌드 명령
    if (/npm run build|tsc\b|cargo build|go build/.test(cmd)) {
      const msg = code === 0 ? "빌드 완료." : "빌드 실패. 에러를 확인하세요.";
      await speakHook(msg, cfg);
      return;
    }

    // 테스트 — pass/fail 파싱
    if (/npm test|pytest|cargo test|go test/.test(cmd)) {
      const passed = out.match(/(\d+)\s*(passed|passing)/)?.[1];
      const failed = out.match(/(\d+)\s*(failed|failing)/)?.[1];
      let msg = "";
      if (failed && parseInt(failed) > 0) {
        msg = `테스트 ${failed}개 실패${passed ? `, ${passed}개 통과` : ""}.`;
      } else if (passed) {
        msg = `전체 ${passed}개 통과.`;
      }
      if (msg) await speakHook(msg, cfg);
      return;
    }

    // 명령 실패 (catch-all)
    if (code !== 0) {
      const snippet = cmd.split(" ").slice(0, 3).join(" ");
      await speakHook(`명령 실패: ${snippet}.`, cfg);
    }
  } catch { /* JSON 파싱 실패 시 무시 */ }
  process.exit(0);
}
settings.json — 훅 등록
"PostToolUse": [
  {
    "matcher": "Bash",
    "hooks": [{
      "type": "command",
      "command": "/path/to/voice-persona/hooks/post-tool-bash.sh",
      "timeout": 15
    }]
  }
],
"PreToolUse": [
  {
    "matcher": "Bash",
    "hooks": [{
      "type": "command",
      "command": "/path/to/voice-persona/hooks/pre-tool-bash.sh",
      "timeout": 5
    }]
  }
]

구현 우선순위 로드맵

순위훅 + 조건발화 예가치복잡도
1 PostToolUse Bash exitCode ≠ 0 "명령 실패: npm run build." 🔴 즉시 인지 낮음
2 PostToolUse Bash 테스트 결과 파싱 "테스트 3개 실패, 72개 통과." 🔴 정량 피드백 낮음
3 PostToolUse Bash 빌드 성공 "빌드 완료." 🟠 완료 확인 매우 낮음
4 Notification 훅 연동 알림 메시지 원문 낭독 🟠 화면 불필요 낮음
5 PreToolUse Bash 빌드·테스트 착수 "빌드를 시작합니다." 🟡 예고 UX 낮음
6 PreToolUse Bash 파괴적 명령 경고 "되돌릴 수 없는 삭제 작업입니다." 🟡 안전 경고 낮음
7 PostToolUse Bash git commit "커밋 완료." 🟢 진행 추적 낮음
8 PreToolUse Agent 파견 알림 "에이전트를 파견합니다." 🟢 팀 가시성 낮음
소음 방지 원칙:
Read, Edit(소규모), Glob, Grep 같이 빈번하고 짧게 끝나는 도구는 voice 대상에서 제외합니다. "결과가 없으면 말하지 않는다" — 빌드 성공·테스트 전부 통과처럼 명확한 신호가 있을 때만 발화합니다.
