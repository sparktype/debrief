🔀 hook_handlers.py (423줄 — 최대 모듈)

모든 hook 이벤트 처리 함수를 담은 핵심 모듈. 트랜스크립트 파싱, 명령 분류, 진단, 설정 관리, 재생 제어까지 광범위한 역할을 담당한다.

  • _derive_transcript_path(): 환경변수에서 Claude 트랜스크립트 파일 경로 조합
  • _extract_last_assistant_text(): JSONL 트랜스크립트 역순 스캔 → 마지막 assistant 텍스트 추출
  • classify_pre_tool_bash(): regex 기반 명령 위험도 분류 (classify-rules.json 우선, 하드코딩 폴백)
  • classify_post_tool_bash(): 빌드/테스트 결과 텍스트 생성

🤖 llm_client.py (47줄)

HMG Hub OpenAI 호환 API 래퍼. chat_completion() 단일 퍼블릭 함수.

  • 환경변수: HUB_API_KEY, HUB_BASE_URL, HUB_PROJECT_ID
  • SSL 검증 비활성화(verify=False) — HMG 사내 프록시 대응
  • API 키 미설정 시 조용히 빈 문자열 반환

🔊 player.py (155줄)

TTS 오케스트레이션 코어. EdgeTTS 및 Supertonic → spool 큐 → 폴백 체인을 구현한다.

  • speak_hook(): 일반 hook용. EdgeTTS MP3 → spool enqueue
  • speak_agent(): 서브에이전트용. Supertonic WAV → spool enqueue
  • spool 큐: /tmp/tts-spool/에 파일명으로 속도 인코딩 ({uid}_{speed*100}.{ext})
  • SSL 패치: 모듈 로드 시 edge_tts.communicate._SSL_CTX를 CERT_NONE 컨텍스트로 교체

💡 skill_recommender.py (169줄)

Claude 트랜스크립트 분석 → LLM 호출 → 유용한 스킬 추천. 쿨다운으로 중복 추천 방지.

  • 최근 3개 트랜스크립트 파일(각 최대 50줄)을 컨텍스트로 전달
  • 60초 인메모리 캐시로 파일 I/O 최소화
  • 쿨다운: skill-cooldowns.json에 ISO 타임스탬프 저장

4. 잠재적 문제점 및 개선 포인트

🔴 에러 핸들링 — Silent Failure 패턴

문제: hook_handlers.py의 많은 함수가 except Exception: pass 또는 except Exception: return ""으로 처리해 실패 원인을 완전히 삼킨다. llm_client.py도 모든 예외를 빈 문자열로 반환.

영향: LLM 호출이 조용히 실패해도 TTS가 fallback으로만 동작하기 때문에 사용자가 알아채기 어렵다. 디버깅 시 로그가 없어 원인 추적 불가.

개선: 최소한 logging.debug()로 예외를 기록하거나, health 결과에 마지막 오류를 포함시키는 구조 권장.

🟡 비동기/동기 혼용

문제: skill_recommender.py의 read_recent_transcripts()는 동기 함수인데, handle_hook_suggest()는 async 컨텍스트에서 직접 호출한다.

파일 크기가 작으면 문제없지만, 대용량 트랜스크립트가 있을 때 이벤트 루프를 블록할 수 있다.

개선: loop.run_in_executor(None, read_recent_transcripts)로 스레드 풀 오프로드.

🟡 글로벌 뮤터블 상태

문제: _classify_rules_cache (hook_handlers.py)와 _transcript_cache (skill_recommender.py)가 모듈 레벨 전역 변수. 단일 프로세스에서는 정상이지만, classify-rules.json이 변경돼도 재시작 없이는 갱신되지 않는다.

개선: rules cache에 파일 mtime 기반 무효화 추가 (transcript cache는 60s TTL이 있어 양호).

🟡 이중 타임아웃 (Double Timeout)

문제: speak_agent()에서 _generate_supertonic()는 이미 timeout파라미터를 받는데, asyncio.wait_for()로 동일한 값으로 다시 감싼다. 실질적으로 동일한 타임아웃이 두 번 적용된다.

영향: 무해하지만 코드 혼란 유발. httpx의 내부 타임아웃이 먼저 발동해 wait_for가 의미 없을 수 있다.

개선: _generate_supertonic의 timeout 파라미터 제거 후 wait_for로만 제어.

🔴 SSL 검증 전역 비활성화

현황: 두 곳에서 SSL 검증이 비활성화된다.
  • player.py: edge_tts.communicate._SSL_CTX 교체 (모듈 로드 시 전역 적용)
  • llm_client.py: httpx.AsyncClient(verify=False)
  • hook_handlers.py health check: httpx.AsyncClient(verify=False)
HMG 사내망 특성상 불가피하지만, edge_tts 내부 컨텍스트를 직접 패치하는 방식은 라이브러리 업그레이드 시 속성명이 바뀔 수 있어 취약하다.

개선: 패치 전 hasattr(_ec, '_SSL_CTX') 검사 추가. 또는 certifi 번들에 HMG CA를 추가하는 방식으로 전환.

🟡 하드코딩된 경로/주소

SPOOL_DIR = Path("/tmp/tts-spool"), TTS_SERVER_URL = "http://localhost:7777"가 player.py에 하드코딩되어 있다. Config에서 관리하지 않으므로 환경별 커스터마이징이 불가.

🟡 handle_hook_suggest 전체 타임아웃 없음

LLM 추천(recommend_skill) 호출은 30s httpx 타임아웃만 있고, 전체 hook 실행에 대한 외부 타임아웃이 없다. Claude Code hook이 응답 대기하는 경우 블록 유발 가능.

✅ 잘 설계된 부분

  • 폴백 체인: EdgeTTS 실패 → HTTP TTS → subprocess → macOS say. 단계적으로 잘 구성됨.
  • spool 큐 설계: 파일명에 속도를 인코딩해 .meta 파일 없이도 재생기가 독립적으로 동작 가능.
  • health 진단: 5개 컴포넌트를 asyncio.gather로 병렬 체크하는 구조가 효율적.
  • voice_router 순수성: 외부 의존성 없이 JSON 파싱만 수행 — 테스트하기 쉽다.
  • Config graceful fallback: JSON 파싱 실패 시 기본값으로 조용히 복구.
  • 쿨다운 관리: ISO 타임스탬프 기반으로 재시작 이후에도 쿨다운 유지.
