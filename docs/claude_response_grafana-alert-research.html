방법 1 — Grafana Webhook Contact Point 사내망 적합성: 상

개요

Grafana가 알럿 발생 시 지정한 HTTP 엔드포인트로 직접 POST 요청을 보내는 Push 방식이다. Mac 로컬에서 HTTP 서버를 열어 수신한다.

지원 버전
Grafana 8.x 이상 Unified Alerting에서 지원. 현재 기본 알럿 시스템(Legacy Alerting은 9.x에서 제거됨). Grafana Cloud 포함.

Unified Alerting vs Legacy Alerting

항목Unified Alerting (현행)Legacy Alerting (구형, 제거됨)
버전Grafana 8+ (기본), 9+에서 Legacy 제거Grafana 7 이하
Webhook 설정Alerting → Contact Points → WebhookAlerting → Notification channels → Webhook
페이로드 형식Alertmanager 호환 JSON다른 스키마 (간단한 구조)
그룹핑Notification Policy로 그룹 제어개별 알럿 단위 발송

핵심 필드 — Firing / Resolved 판단

필드Firing 값Resolved 값설명

구현 플로우

Grafana 알럿 발생 → Contact Point (Webhook) 설정된 URL로 POST → Mac 로컬 HTTP 서버 (FastAPI / aiohttp) 수신 → fingerprint 로 중복 체크 → status 판단 → TTS 발화

Mac 로컬 수신 서버 예시

from fastapi import FastAPI, Request
import asyncio

app = FastAPI()
seen: dict[str, str] = {}  # fingerprint → last status

@app.post("/grafana-alert")
async def receive_alert(request: Request):
    body = await request.json()
    for alert in body.get("alerts", []):
        fp   = alert["fingerprint"]
        stat = alert["status"]   # "firing" | "resolved"
        name = alert["labels"].get("alertname", "Unknown")
        summary = alert["annotations"].get("summary", "")

        # 중복·상태 미변경 건너뜀
        if seen.get(fp) == stat:
            continue
        seen[fp] = stat

        emoji = "🔴" if stat == "firing" else "🟢"
        text  = f"{emoji} {name}: {summary}" if stat == "firing" \
                else f"알럿 해소: {name}"

        # TTS spool에 enqueue
        await enqueue_tts(text)
    return {"ok": True}
사내망 주의
Grafana 서버가 Mac 로컬 엔드포인트에 접근할 수 있어야 한다. 사내망 방화벽·NAT 환경에서 Grafana → Mac 직접 push가 차단될 수 있으므로 네트워크 경로 확인이 선행되어야 한다.

Webhook Contact Point 설정 경로

Grafana UI
  → Alerting → Contact Points → "+ Add contact point"
  → Type: Webhook
  → URL: http://<mac-ip>:8888/grafana-alert
  → (Optional) HTTP Method: POST
  → (Optional) Authorization Header: Bearer <token>

방법 2 — Grafana 내장 Alertmanager API Polling 사내망 적합성: 중

개요

Grafana 내장 Alertmanager가 노출하는 Alertmanager v2 호환 REST API를 주기적으로 폴링하는 Pull 방식이다. Mac에서 Grafana 서버로 요청을 보내므로 방화벽 방향이 반대다.

주요 엔드포인트

엔드포인트설명응답 필터
GET /api/alertmanager/grafana/api/v2/alerts 현재 active 알럿 목록 query: active, silenced, inhibited, filter
GET /api/alertmanager/grafana/api/v2/alerts/groups 그룹핑된 알럿 목록 동일
GET /api/alertmanager/grafana/api/v2/status Alertmanager 상태 정보 —

인증 방법

Service Account Token (권장)
curl -H "Authorization: Bearer glsa_xxx..." \
  http://grafana:3000/api/alertmanager/grafana/api/v2/alerts

Administration → Service Accounts → Add token
Role: Viewer 이상 필요

Basic Auth (구형, 비권장)
curl -u "admin:password" \
  http://grafana:3000/api/alertmanager/grafana/api/v2/alerts

Grafana 9+에서 API Key 방식은 Service Account로 전환됨

상태 변화 감지 — Polling 로직

import asyncio, httpx
from datetime import datetime, timezone

GRAFANA_URL = "http://grafana.internal:3000"
TOKEN = "glsa_xxxx"
POLL_INTERVAL = 30  # 초

seen: dict[str, str] = {}  # fingerprint → "active" | "resolved"

def is_resolved(alert: dict) -> bool:
    ends_at = alert.get("endsAt", "")
    if not ends_at or ends_at.startswith("0001"):
        return False
    try:
        t = datetime.fromisoformat(ends_at.replace("Z", "+00:00"))
        return t < datetime.now(timezone.utc)
    except ValueError:
        return False

async def poll_alerts():
    async with httpx.AsyncClient(verify=False) as client:  # HMG SSL 우회
        while True:
            try:
                r = await client.get(
                    f"{GRAFANA_URL}/api/alertmanager/grafana/api/v2/alerts",
                    headers={"Authorization": f"Bearer {TOKEN}"},
                    params={"active": "true", "silenced": "false"}
                )
                r.raise_for_status()
                alerts = r.json()

                current_fps = set()
                for alert in alerts:
                    fp   = alert["fingerprint"]
                    name = alert["labels"].get("alertname", "Unknown")
                    current_fps.add(fp)

                    resolved = is_resolved(alert)
                    new_state = "resolved" if resolved else "active"

                    if seen.get(fp) != new_state:
                        seen[fp] = new_state
                        text = f"알럿 해소: {name}" if resolved \
                               else f"알럿 발생: {name}"
                        await enqueue_tts(text)

                # 이전에 있었지만 지금 없는 알럿 = 해소됨
                for fp in list(seen.keys()):
                    if fp not in current_fps and seen[fp] == "active":
                        seen[fp] = "resolved"
                        await enqueue_tts("알럿이 해소되었습니다.")

            except Exception as e:
                print(f"Polling error: {e}")

            await asyncio.sleep(POLL_INTERVAL)

asyncio.run(poll_alerts())
HMG SSL 우회
사내망 SSL 인터셉트 프록시 환경에서 httpx.AsyncClient(verify=False) 또는 시스템 CA 번들 경로 지정 필요. CLAUDE.md 환경 섹션 참조.

방법 3 — Grafana Alerting Rules API Polling 사내망 적합성: 하

개요

알럿 룰 정의를 읽어오는 Provisioning API와, 룰 평가 상태를 읽는 Ruler API를 조합하는 방식이다. 실시간 알럿 상태보다는 룰 관리 목적으로 설계되어 있어 모니터링 목적으로는 적합성이 낮다.

관련 엔드포인트

엔드포인트용도비고
GET /api/v1/provisioning/alert-rules 알럿 룰 목록 조회 (룰 정의) 현재 Firing 여부 미포함
GET /api/v1/provisioning/alert-rules/{uid} 특정 룰 상세 조회 —
GET /api/prometheus/grafana/api/v1/alerts Prometheus 호환 알럿 상태 조회 Firing 상태만 반환
GET /api/ruler/grafana/api/v1/rules Ruler 기반 룰 평가 그룹 조회 내부 구현용, 불안정

Prometheus 호환 알럿 엔드포인트 응답

{
  "status": "success",
  "data": {
    "alerts": [
      {
        "labels": {

방법 3 한계
  • /api/v1/provisioning/alert-rules는 룰 정의만 반환 — 현재 Firing 여부 없음
  • Prometheus 호환 엔드포인트는 현재 Firing 알럿만 반환, Resolved 전환 감지 불가
  • Resolved 감지를 위해 이전 상태를 별도 저장해야 하고, 레이스 컨디션 가능성 존재
