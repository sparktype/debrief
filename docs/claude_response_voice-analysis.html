🔴 루트 원인 — No module named hook_voice

stop.sh는 PYTHONPATH를 설정하지 않고 .venv/bin/python -m hook_voice를 실행합니다. Python의 -m 플래그는 현재 작업 디렉토리(CWD)를 sys.path에 추가하여 패키지를 탐색합니다. hook이 summary-voice-mcp가 아닌 다른 CWD에서 실행되면 hook_voice 패키지를 찾지 못해 즉시 종료되고, 발화가 일어나지 않습니다.

기술적 원인 — Python -m 동작 방식

# stop.sh 현재 코드 (문제 있음)
VENV_PY="$SCRIPT_DIR/../.venv/bin/python"
echo "$PAYLOAD" | nohup "$VENV_PY" -m hook_voice hook ...
# CWD가 어디든 -m은 CWD를 sys.path[0]으로 추가 → CWD에 hook_voice 없으면 실패
# 직접 테스트 결과
cd /tmp && .venv/bin/python -m hook_voice hook → 실패 (No module named hook_voice)
cd /project && .venv/bin/python -m hook_voice hook → 성공 (정상 실행)

hook_voice는 pyproject.toml / setup.py 없이 순수 디렉토리 패키지로만 존재합니다. pip install -e .로 site-packages에 설치된 게 아니므로 CWD에 의존합니다.

로그 전체(9,213줄)의 약 24%를 Grafana 폴링 에러가 차지합니다. 발화 자체와는 무관하지만 로그 분석을 방해하고 불필요한 HTTP 부하를 만듭니다.

해결 방안

방안 1 (권장) — stop.sh에 PYTHONPATH 추가

#!/usr/bin/env bash
PAYLOAD=$(cat)
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
PROJECT_DIR="$SCRIPT_DIR/.."
VENV_PY="$PROJECT_DIR/.venv/bin/python"
echo "$PAYLOAD" | nohup env PYTHONPATH="$PROJECT_DIR" \
  "$VENV_PY" -m hook_voice hook \
  >> /tmp/voice-notification-debug.log 2>&1 &
disown $!; exit 0

모든 hook 스크립트(subagent-stop.sh, session-start.sh, prompt-submit.sh, notification.sh)에 동일하게 적용 필요.

방안 2 — pip install -e . (영구적 해결)

# pyproject.toml 최소 생성 후 개발 모드 설치
.venv/bin/pip install -e .
# → hook_voice가 site-packages에 링크 → CWD 무관하게 작동

이 방법은 CWD에 완전히 독립적으로 작동합니다.

한 줄 요약

TTS 서버·Supertonic·Player는 모두 정상이지만, hook 실행 CWD가 summary-voice-mcp가 아닌 경우 hook_voice 모듈을 찾지 못해 발화가 일어나지 않습니다. 특히 arch-delphi 세션과 워크트리 세션에서 오늘만 2,000회 이상 실패했습니다.
