2. 개선 방안 (효과순)

① Supertonic steps 줄이기 최우선 — 0.55s 절감

서브에이전트 발화는 짧은 한 문장(평균 20~40자)입니다. diffusion steps가 많을수록 품질이 높아지지만, 이 길이에서는 steps=6이면 충분합니다.

steps생성 시간절감파일 크기
12 (현재)1.62s—326 KB

6 (권장)1.07s0.55s326 KB

코드 변경 없이 voice-map.json만 수정하면 됩니다.

# voice-map.json
{
  "supertonic": {
    "lang": "ko",
    "steps": 6       # 12 → 6 으로 변경 (1.62s → 1.07s, 34% 절감)
  }
}

② 텍스트 길이 기반 동적 steps 선택 사항 — 추가 0.2~0.5s

짧은 발화(서브에이전트 공지)에는 적은 steps, 긴 발화(메인 응답)에는 기본 steps를 자동 적용합니다.

def _dynamic_steps(text: str, base_steps: int = 12) -> int:
    """텍스트 길이에 따라 diffusion steps 동적 조정."""
    n = len(text)
    if n < 30:   return 4
    if n < 60:   return 6
    if n < 100:  return 8
    return base_steps

적용 위치: hook_voice/player.py의 speak_agent() 내부에서 steps = _dynamic_steps(text, base_steps)로 교체.

③ 서브에이전트 one_liner LLM 호출 제거 0.2~1s 절감 (LLM 인증 성공 시)

서브에이전트 발화는 25자 이내 한 줄 요약입니다. 규칙 기반 truncation으로 충분하며 LLM 호출을 완전히 제거할 수 있습니다.

async def handle_subagent_stop(raw, agent_type, config):
    ...
    # 기존: LLM one_liner 시도 → 실패 시 규칙 기반 (0.22s)
    # 개선: 서브에이전트는 항상 규칙 기반 (0.00s)
    one_liner = _rule_based_truncate(text, max_chars=25)
    # config.summary_model 호출 완전 제거

현재 LLM이 401 실패 중이라 체감 효과는 없지만, 향후 LLM이 정상 동작 시 0.5~1s를 절감합니다. 서브에이전트 one_liner의 특성상 LLM이 없어도 품질 차이가 거의 없습니다.

④ one_liner + health check 병렬 실행 약 0.05~0.1s

현재 순차로 실행되는 LLM 요약과 Supertonic health check를 asyncio.gather()로 병렬화합니다.

# 기존: 순차 실행
one_liner = await extract_one_liner(text, model)   # 0.22s
speech_ctx = await pipeline.process(one_liner)     # 0.00s
wav = await speak_agent(speak_text, ...)           # 1.62s

# 개선: one_liner + supertonic health check 병렬 실행
async def _prepare():
    liner, alive = await asyncio.gather(
        extract_one_liner(text, model),
        _is_supertonic_alive(port),
    )
    return liner, alive

⑤ Python 프로세스 재사용 (장기 과제) 약 0.15s

매 hook 호출마다 새 Python 프로세스를 시작합니다. hook → TTS server HTTP 호출 방식으로 전환하면 startup 비용을 제거할 수 있습니다. 단, 현재 구조에서 큰 변경이 필요합니다.
